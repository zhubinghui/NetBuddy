# NetCare 架构设计总览

**版本**: 1.0  
**更新日期**: 2026-08-21  
**状态**: 设计中

## 1. 项目简介

NetCare 是一个面向网络运维场景的 AI Agent 框架，基于 **Anthropic Pi** 框架构建。提供以下核心能力：

- **故障在线诊断**: 实时接入网络，自动采集分析日志，提供处理建议
- **故障离线诊断**: 离线根因分析和推荐
- **网络巡检**: 自动化设备巡检检查
- **变更保障**: 基于数字孪生能力进行风险推演和操作回退

## 3. 分层设计详解

### 3.1 用户交互层
- **REST API**: 基于 FastAPI，提供诊断、巡检、变更等接口
- **CLI 工具**: 命令行接口，支持快速诊断和查询
- **Web 界面**: 可视化展示诊断过程、拓扑图、变更模拟结果（可选）

### 3.2 Pi Agent 编排层
该层由多个特化的 Pi Agent 组成，每个 Agent 专注于特定运维场景：

| Agent | 职责 | 输入 | 输出 |
|-------|------|------|------|
| **DiagnosisAgent** | 在线故障诊断 | 故障症状、网络拓扑 | 诊断报告、处理建议 |
| **OfflineDiagAgent** | 离线根因分析 | 日志、配置、拓扑 | 根因分析、根因推荐 |
| **InspectionAgent** | 设备自动巡检 | 巡检计划、设备列表 | 巡检报告、风险列表 |
| **ChangeAgent** | 变更操作执行 | 变更计划、审批状态 | 执行结果、回退方案 |
| **MonitorAgent** | 持续监控 | 指标阈值、告警规则 | 告警推送、异常检测 |

### 3.3 Pi Tools 层
将核心功能封装为可调用的 Tools，支持 Agent 自主决策：

**设备操作工具**:
- `execute_device_command`: 在设备上执行命令
- `collect_device_logs`: 收集设备日志
- `get_device_config`: 获取设备配置
- `check_device_connectivity`: 检查设备连通性

**诊断分析工具**:
- `parse_log_file`: 解析日志文件
- `analyze_root_cause`: 根因分析
- `query_knowledge_base`: 查询知识库
- `compare_configs`: 配置对比

**工作流工具**:
- `request_human_approval`: 请求人工审批
- `write_audit_log`: 写入审计日志
- `simulate_change`: 模拟变更操作
- `execute_rollback`: 执行回滚操作

### 3.4 核心服务层
提供业务逻辑和数据管理服务：

| 服务 | 功能 |
|-----|------|
| **DeviceManager** | 设备连接管理、SSH 连接池、重试策略 |
| **LogProcessor** | 日志采集、解析、标准化、聚合 |
| **DigitalTwin** | 网络拓扑模型、状态同步、变更模拟 |
| **KnowledgeBase** | 故障知识库、规则库、向量检索 |
| **WorkflowEngine** | 工作流编排、状态管理、人工审批 |

### 3.5 基础设施层
数据存储和消息传递：

- **PostgreSQL**: 元数据、配置、审计日志
- **Redis**: 缓存、会话、临时状态
- **Message Queue**: 异步任务队列（RabbitMQ/Redis Queue）
- **File Storage**: 日志文件、配置备份、诊断报告

## 4. 关键设计原则

### 4.1 安全性优先
- ✅ **Human-in-the-loop**: 所有有操作影响的决策都需人工确认
- ✅ **权限管理**: Tool 级别的权限控制
- ✅ **操作审计**: 完整的操作日志记录
- ✅ **操作回滚**: 支持所有操作的回退机制

### 4.2 可靠性
- ✅ **自动重试**: 设备连接故障自动重试
- ✅ **幂等性**: 所有操作支持幂等性设计
- ✅ **错误处理**: 完善的错误捕获和恢复机制
- ✅ **分布式**: 支持水平扩展和负载均衡

### 4.3 可扩展性
- ✅ **插件式 Agent**: 易于添加新的 Agent
- ✅ **Tool 扩展**: 新增功能通过 Tool 扩展
- ✅ **多协议支持**: SSH、Telnet、SNMP、REST API
- ✅ **模型可替换**: LLM 模型可灵活配置

### 4.4 可观测性
- ✅ **完整日志**: 所有操作都有详细日志
- ✅ **链路追踪**: 请求链路追踪
- ✅ **性能指标**: 关键操作的性能监控
- ✅ **可视化**: 诊断过程和结果可视化
